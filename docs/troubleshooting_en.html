USB Issues: USB2 or USB3, but not both simultaneously

Problem Description

In some systems, especially with older hardware or specific BIOS configurations, it may occur that USB2 ports work correctly or USB3 ports work correctly, but not both simultaneously. This issue can manifest as USB ports that stop responding or devices that are not recognized properly.

Possible Causes

  • Issues with USB driver in the kernel
  • Incorrect USB power configuration in BIOS
  • Driver or resource conflicts
  • USB hardware with compatibility issues

Solution

Rather than a general procedure, the solution depends on specific hardware and distribution. It is recommended:

  1. Check for kernel and driver updates
  2. Update BIOS to the latest available firmware
  3. Test different USB ports and devices
  4. Check system logs: dmesg | grep -i usb

IOMMU Issues in AMD Ryzen Processors

Problem Description

IOMMU (Input-Output Memory Management Unit) issues in AMD Ryzen processors can manifest as USB devices not working correctly, boot problems, or issues when using virtual machines with hardware passthrough.

What does the IOMMU controller do?

Some PCI devices can only handle 32-bit addresses through DMA access (it's a legacy issue). So some PCI devices can only use the first 4GB of memory, even on modern 64-bit systems.

When the addressable range of a device (through DMA) is limited and no IOMMU exists, the device might not be able to reach all of physical memory. In this case a region of system memory that the device can address is reserved (within the first 4GB of memory), and the device is programmed to DMA to this reserved area. The processor then copies the result to the target memory that was beyond the "reach" of the device. That takes a lot of processor resources. This method is known as bounce buffering (also known as SWIOTLB or software IOMMU).

Hardware IOMMUs are physical devices that translate (remaps) device DMA addresses (32-bit) to 64-bit physical addresses so devices could access all of physical memory without processor help.

Solutions for IOMMU Issues

Solution 1: Disable IOMMU in BIOS

Pros: Easy. No Linux setup needed.
Cons: Loss of performance when Virtual Machines used.

Solution 2: Kernel parameter (software emulation)

iommu=soft

or

amd_iommu=off

This is equivalent to the previous option. We are telling the kernel not to use the IOMMU hardware but instead emulate it through software. Is the default mode for Intel processors.
Pros: You don't need to disable IOMMU in BIOS. Is one suitable option if you have dual boot and the other O.S. needs the IOMMU enabled.
Cons: Loss of features when Virtual Machines used.

Solution 3: Force enable IOMMU with passthrough translation

amd_iommu=force_enable iommu=pt

amd_iommu=on is not supported but amd_iommu=force_enable is. Looks like just putting iommu=pt alone works.
Pros: Works. Not a software emulation. 100% hardware accelerated. Passthrough enabled.
Cons: iommu=pt is incompatible with Secure Memory Encryption (RAM encryption present on Ryzen Pro processors).

Solution 4: Force enable IOMMU without passthrough

amd_iommu=force_enable

Same as Solution 3 but without passthrough.

Solution 5: Disable ATS (Address Translation Services)

pci=noats

Not widely tested. Almost no information available.

Apply Recommended Solution (Solution 3)

Solution 3 is the one that doesn't penalize virtualization features. To apply it:

  1. Edit /etc/default/grub:
    2. sudo nano /etc/default/grub
  2. Add amd_iommu=force_enable iommu=pt at the end of the GRUB_CMDLINE_LINUX_DEFAULT line:
    3. GRUB_CMDLINE_LINUX_DEFAULT="quiet splash amd_iommu=force_enable iommu=pt"
  3. Update GRUB:
    4. sudo update-grub
  4. Reboot and enter BIOS. Enable:
    • IOMMU
    • SVM mode (virtualization support) in Advanced->CPU configuration->SVM mode
  5. Save settings and reboot.

After rebooting, Ubuntu will boot correctly, rear USB ports should work, and virtual machines will be able to benefit from an operating IOMMU with the passthru option. This option enables virtual machines to directly use hardware components from the host (a second GPU, NVME drive, Ethernet, WiFi, USB...).

Restart Cinnamon when it hangs

Problem Description

The Cinnamon desktop environment can occasionally hang, resulting in an unresponsive or frozen user interface.

Solution

To restart Cinnamon from the command line:

export DISPLAY=:0; cinnamon & exit

Install an Alias to Restart Cinnamon

To facilitate the process, you can install an alias in your ~/.bashrc file:

echo "alias refresh-cinnamon='export DISPLAY=:0; cinnamon & exit'" >> ~/.bashrc

Then, you'll just need to run refresh-cinnamon from any terminal to restart Cinnamon.

Create NFS Shared Directory

Problem Description

Sharing directories on the local network can be tricky if not configured correctly. NFS (Network File System) is an efficient solution for sharing directories in Linux networks.

NFS Server Configuration

  1. Install the NFS server:
    2. sudo apt install nfs-kernel-server
  2. Configure the directories to share by editing /etc/exports:
    3. sudo nano /etc/exports
  3. Add a line to share your directory (example for 192.168.0.x network):
    4. /home/user/Shared 192.168.0.1/24(rw,no_subtree_check,async)
  4. Export directories:
    5. sudo exportfs -arv
  5. Enable and start the service:
    6. sudo systemctl enable nfs-kernel-server
sudo systemctl start nfs-kernel-server

NFS Client Configuration

  1. Install NFS packages:
    2. sudo apt install nfs-common
  2. Create a mount point:
    3. sudo mkdir -p /Shared
  3. Verify that the NFS server is sharing directories:
    4. showmount -e 192.168.0.xxx
  4. Mount the remote directory:
    5. sudo mount 192.168.0.xxx:/home/user/Shared /Shared

Permanent Mount

  1. Edit /etc/fstab:
    2. sudo nano /etc/fstab
  2. Add a line for automatic mounting:
    3. 192.168.0.xxx:/home/user/Shared /Shared nfs rw,async 0 0
  3. Test the configuration:
    4. mount -a

Mount Network Drives (SMB/CIFS)

Problem Description

Mounting shared network drives from Windows or other SMB systems can be tricky if not configured correctly.

Manual Solution

To temporarily mount a network drive:

sudo mount -t cifs //SERVER/SHARE /mount/point -o username=USERNAME,password=PASSWORD

Using Credentials File (Recommended)

For increased security, create a credentials file:

sudo nano ~/.smbcreds

File content:

username=USERNAME
password=PASSWORD
domain=DOMAIN

Set secure permissions:

chmod 600 ~/.smbcreds

Mount using the credentials file:

sudo mount -t cifs //SERVER/SHARE /mount/point -o credentials=/home/user/.smbcreds,uid=user,gid=user

Permanent Mount in /etc/fstab

To mount automatically at boot:

//SERVER/SHARE /mount/point cifs credentials=/home/user/.smbcreds,uid=user,gid=user,file_mode=0777,dir_mode=0777,iocharset=utf8,vers=3.0 0 0

Create Start Menu Shortcuts

Problem Description

It's common to need to create custom shortcuts for applications or scripts in the start menu.

Solution

Shortcuts are saved with .desktop extension in:

  • For a specific user: ~/.local/share/applications
  • For the entire system: /usr/share/applications

Shortcut Example

Create a app_name.desktop file with the following content:

#!/usr/bin/env xdg-open
[Desktop Entry]
Name=Application Name
Name[en_US]=Application Name
Comment=Description of the application
Icon=/path/to/icon.png
Exec=command to execute
Path=/path/to/execute/from
Type=Application
Terminal=false
Actions=
StartupNotify=false
Categories=Application;

Important Considerations

  1. After creating and editing the .desktop file, execute it (double-click) and respond to the question as "TRUSTED".
  2. All directories and shortcuts that contain spaces in their names should be written in double quotes.

Concrete Example

Shortcut for a backup script:

#!/usr/bin/env xdg-open
[Desktop Entry]
Name=Backup Script
Name[en_US]=Backup Script
Comment=Performs backup of important documents
Icon=/usr/share/icons/backup-icon.png
Exec=/home/user/scripts/backup.sh
Path=/home/user/scripts/
Type=Application
Terminal=true
Actions=
StartupNotify=false
Categories=Utility;
