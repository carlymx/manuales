Problemas con USB: USB2 o USB3, pero no ambos a la vez

Descripción del Problema

En algunos sistemas, especialmente con hardware más antiguo o con configuraciones específicas de la BIOS, puede ocurrir que los puertos USB2 funcionen correctamente o los puertos USB3 funcionen correctamente, pero no ambos simultáneamente. Este problema puede manifestarse como puertos USB que dejan de responder o dispositivos que no se reconocen correctamente.

Causas Probables

  • Problemas con el controlador USB en el kernel
  • Configuración incorrecta de energía USB en la BIOS
  • Conflicto de controladores o recursos
  • Hardware USB con problemas de compatibilidad

Solución

En lugar de un procedimiento general, la solución depende del hardware específico y la distribución. Se recomienda:

  1. Verificar actualizaciones del kernel y controladores
  2. Actualizar la BIOS al último firmware disponible
  3. Probar diferentes puertos USB y dispositivos
  4. Revisar los registros del sistema: dmesg | grep -i usb

Problemas con IOMMU en Procesadores AMD Ryzen

Descripción del Problema

Los problemas de IOMMU (Input-Output Memory Management Unit) en procesadores AMD Ryzen pueden manifestarse como dispositivos USB que no funcionan correctamente, problemas de arranque, o problemas al usar máquinas virtuales con paso directo (passthrough) de hardware.

¿Qué hace el controlador IOMMU?

Algunos dispositivos PCI solo pueden manejar direcciones de 32 bits a través del acceso DMA (es un asunto heredado). Por lo tanto, algunos dispositivos PCI solo pueden usar los primeros 4 GB de memoria, incluso en sistemas modernos de 64 bits.

Cuando el rango direccionable de un dispositivo (a través de DMA) es limitado y no existe IOMMU, es posible que el dispositivo no pueda acceder a toda la memoria física. En este caso, se reserva una región de la memoria del sistema a la que el dispositivo puede dirigirse (dentro de los primeros 4 GB de memoria), y el dispositivo se programa para DMA en esta área reservada. Luego, el procesador copia el resultado en la memoria de destino que estaba más allá del "alcance" del dispositivo. Eso requiere muchos recursos del procesador. Este método se conoce como almacenamiento en búfer de rebote (también conocido como SWIOTLB o software IOMMU).

Las IOMMU de hardware son dispositivos físicos que traducen (reasignan) las direcciones DMA del dispositivo (32 bits) a direcciones físicas de 64 bits para que los dispositivos puedan acceder a toda la memoria física sin la ayuda del procesador.

Soluciones para Problemas de IOMMU

Solución 1: Deshabilitar IOMMU en BIOS

Pros: Fácil. No se necesita configuración de Linux.
Contras: Pérdida de rendimiento cuando se utilizan máquinas virtuales.

Solución 2: Parámetro del kernel (emulación de software)

iommu=soft

o

amd_iommu=off

Esto es equivalente a la opción anterior. Le estamos diciendo al kernel que no use el hardware IOMMU, sino que lo emule a través del software. Es el modo predeterminado para los procesadores Intel.
Pros: No es necesario deshabilitar IOMMU en BIOS. Es una opción adecuada si tiene arranque dual y el otro sistema operativo necesita IOMMU habilitado.
Contras: Pérdida de funciones cuando se utilizan máquinas virtuales.

Solución 3: Forzar activación de IOMMU con traducción passthrough

amd_iommu=force_enable iommu=pt

amd_iommu=on no es compatible, pero amd_iommu=force_enable sí lo es. Parece que simplemente poner iommu=pt solo funciona.
Pros: Funciona. No es una emulación de software. 100% acelerado por hardware. Passthrough habilitado.
Contras: iommu=pt es incompatible con Secure Memory Encryption (cifrado de RAM presente en los procesadores Ryzen Pro).

Solución 4: Forzar activación de IOMMU sin passthrough

amd_iommu=force_enable

Igual que la solución 3 pero sin passthrough.

Solución 5: Deshabilitar ATS (Address Translation Services)

pci=noats

No probado ampliamente. Casi sin información disponible.

Aplicar la Solución Recomendada (Solución 3)

La solución 3 es la que no penaliza las funciones de virtualización. Para aplicarla:

  1. Edita /etc/default/grub:
    2. sudo nano /etc/default/grub
  2. Agrega amd_iommu=force_enable iommu=pt al final de la línea GRUB_CMDLINE_LINUX_DEFAULT:
    3. GRUB_CMDLINE_LINUX_DEFAULT="quiet splash amd_iommu=force_enable iommu=pt"
  3. Actualiza GRUB:
    4. sudo update-grub
  4. Reinicia y entra en la BIOS. Habilita:
    • IOMMU
    • SVM mode (soporte de virtualización) en Avanzado->Configuración de CPU->Modo SVM
  5. Guarda la configuración y reinicia.

Después del reinicio, Ubuntu debería arrancar correctamente, los puertos USB traseros deberían funcionar y las máquinas virtuales podrían beneficiarse de un IOMMU operativo con la opción passthru. Esta opción permite que las máquinas virtuales usen directamente componentes de hardware del host (una segunda GPU, unidad NVME, Ethernet, WiFi, USB...).

Reiniciar Cinnamon cuando se cuelga

Descripción del Problema

El entorno de escritorio Cinnamon puede colgarse ocasionalmente, lo que resulta en una interfaz de usuario no receptiva o congelada.

Solución

Para reiniciar Cinnamon desde la línea de comandos:

export DISPLAY=:0; cinnamon & exit

Instalar un Alias para Reiniciar Cinnamon

Para facilitar el proceso, puedes instalar un alias en tu archivo ~/.bashrc:

echo "alias refrescar-cinnamon='export DISPLAY=:0; cinnamon & exit'" >> ~/.bashrc

Luego, solo tendrás que ejecutar refrescar-cinnamon desde cualquier terminal para reiniciar Cinnamon.

Crear Directorio Compartido NFS

Descripción del Problema

Compartir directorios en la red local puede ser complicado si no se configura correctamente. NFS (Network File System) es una solución eficiente para compartir directorios en redes Linux.

Configuración del Servidor NFS

  1. Instala el servidor NFS:
    2. sudo apt install nfs-kernel-server
  2. Configura los directorios a compartir editando /etc/exports:
    3. sudo nano /etc/exports
  3. Agrega una línea para compartir tu directorio (ejemplo para red 192.168.0.x):
    4. /home/usuario/Shared 192.168.0.1/24(rw,no_subtree_check,async)
  4. Exporta los directorios:
    5. sudo exportfs -arv
  5. Habilita y arranca el servicio:
    6. sudo systemctl enable nfs-kernel-server
sudo systemctl start nfs-kernel-server

Configuración del Cliente NFS

  1. Instala los paquetes NFS:
    2. sudo apt install nfs-common
  2. Crea un punto de montaje:
    3. sudo mkdir -p /Shared
  3. Verifica que el servidor NFS esté compartiendo directorios:
    4. showmount -e 192.168.0.xxx
  4. Monta el directorio remoto:
    5. sudo mount 192.168.0.xxx:/home/usuario/Shared /Shared

Montaje Permanente

  1. Edita /etc/fstab:
    2. sudo nano /etc/fstab
  2. Agrega una línea para el montaje automático:
    3. 192.168.0.xxx:/home/usuario/Shared /Shared nfs rw,async 0 0
  3. Prueba la configuración:
    4. mount -a

Montar Unidades de Red (SMB/CIFS)

Descripción del Problema

Montar unidades de red compartidas desde Windows u otros sistemas SMB puede ser complicado si no se configura correctamente.

Solución Manual

Para montar una unidad de red temporalmente:

sudo mount -t cifs //SERVIDOR/COMPARTIDO /punto/montaje -o username=USUARIO,password=CONTRASEÑA

Usando Archivo de Credenciales (Recomendado)

Para mayor seguridad, crea un archivo de credenciales:

sudo nano ~/.smbcreds

Contenido del archivo:

username=USUARIO
password=CONTRASEÑA
domain=DOMINIO

Establece permisos seguros:

chmod 600 ~/.smbcreds

Monta usando el archivo de credenciales:

sudo mount -t cifs //SERVIDOR/COMPARTIDO /punto/montaje -o credentials=/home/usuario/.smbcreds,uid=usuario,gid=usuario

Montaje Permanente en /etc/fstab

Para montar automáticamente al arrancar:

//SERVIDOR/COMPARTIDO /punto/montaje cifs credentials=/home/usuario/.smbcreds,uid=usuario,gid=usuario,file_mode=0777,dir_mode=0777,iocharset=utf8,vers=3.0 0 0

Crear Accesos Directos en el Menú Inicio

Descripción del Problema

Es común necesitar crear accesos directos personalizados para aplicaciones o scripts en el menú de inicio del escritorio.

Solución

Los accesos directos se guardan con extensión .desktop en:

  • Para un usuario específico: ~/.local/share/applications
  • Para todo el sistema: /usr/share/applications

Ejemplo de Acceso Directo

Crea un archivo nombre_app.desktop con el siguiente contenido:

#!/usr/bin/env xdg-open
[Desktop Entry]
Name=Nombre de la Aplicación
Name[es_ES]=Nombre de la Aplicación
Comment=Descripción de la aplicación
Icon=/ruta/a/icono.png
Exec=comando a ejecutar
Path=/ruta/para/ejecutar
Type=Application
Terminal=false
Actions=
StartupNotify=false
Categories=Application;

Consideraciones Importantes

  1. Después de crear y editar el archivo .desktop, ejecútalo (doble clic) y responde a la pregunta como "CONFIABLE".
  2. Todos los directorios y accesos que contengan espacios en sus nombres deberán escribirse entre comillas dobles.

Ejemplo Concreto

Acceso directo para un script de backup:

#!/usr/bin/env xdg-open
[Desktop Entry]
Name=Backup Script
Name[es_ES]=Script de Backup
Comment=Realiza backup de documentos importantes
Icon=/usr/share/icons/backup-icon.png
Exec=/home/usuario/scripts/backup.sh
Path=/home/usuario/scripts/
Type=Application
Terminal=true
Actions=
StartupNotify=false
Categories=Utility;
